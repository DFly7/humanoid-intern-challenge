# Experiment protocol

## Question

Can hand motion from a small personally recorded dataset supply useful robot demonstrations
after explicit geometric retargeting, without pretending phone pixels contain robot actions?

The first experiment is one LIBERO task. The teacher uses the recorded path, a calibrated
coordinate transform, closed-loop robot position feedback, and manually annotated gripper
events. The student is SmolVLA fine-tuned on the **simulator observations/actions generated by
that teacher**. It does not train directly on phone RGB. This makes the embodiment gap explicit,
but leaves a fixed-view bias and possible teacher-specific failures.

## Comparisons to run

| Condition | Purpose |
| --- | --- |
| Replay without speed retiming | Does geometric conversion alone create executable paths? |
| Phone path with speed retiming | Does preserving contact events and slowing reaches help? |
| SmolVLA after adaptation on accepted phone-derived demonstrations | Does the student generalize across initial states? |
| SmolVLA with unmatched/shuffled trajectory ordering, same budget | Is temporal structure from the phone data useful? |

The no-retiming and shuffled-data conditions are proposed ablations; they need separate
implementations and runs. Do not describe them as completed results. A pretrained checkpoint
alone is not a fair Panda performance baseline without matching the action/state convention.

## Keep evaluations separate

- Assign train/validation/test by original video session; report counts and discarded attempts.
- Choose training initial-state IDs, then reserve a disjoint list for validation and final testing.
  For example: 0–9 for training, 10–14 for validation, 15–24 for test, if the chosen task has them.
- Tune calibration and model selection on training/validation only. Freeze both before testing.
- Run each condition on the same held-out initial states and seeds. Count every attempt,
  including collisions, timeouts, and failed grips. Do not select only good-looking videos.
- Report success count / attempted episodes, plus an interval (e.g. Wilson 95%). A single
  simulation clip establishes execution, not reliable task performance.
- Report action-generation p50/p95 latency, hardware, and action chunk length. The rollout
  timer includes preprocessing/selection but excludes simulator stepping and PNG/video I/O.
  Chunk queues make many calls cheap; do not equate median selection time with model forward time.
- Tracking error is meaningful for the teacher. For a VLA it only compares to a reference path;
  task success is the actual LIBERO success predicate, independent of tracking error.

## Evidence to include before submission

1. One original phone clip paired with its simulator replay, plus the manifest and calibration.
2. Number of original recordings, phone-derived attempts, accepted training episodes, and
   rejected attempts with reasons. Export currently rejects failed teacher trajectories.
3. Training configuration, checkpoint identity, dependency versions, hardware, and runtime.
4. Raw per-attempt `metrics.json` files, held-out state IDs, aggregate success, and failure clips.
5. A short account of what changed after examining failures. Useful failures include parallax,
   incorrect contact height, an orientation the fixed-wrist teacher cannot reach, an inaccurate
   gripper event, and camera/initial-state shift in the VLA.

## Current limitations

There is no learned world model or RL improvement in this initial project. There are no
personally collected recordings or trained weights in the initial commit. Dataset export and
SmolVLA adaptation require those recordings and successful retargeted episodes first. A local
synthetic simulation smoke test is useful software evidence and cannot satisfy the challenge.
